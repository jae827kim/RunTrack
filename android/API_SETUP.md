# 실제 API 연결 및 로컬 실행

일반 계정은 실제 회원가입·로그인을 수행하고, 신발과 러닝 기록을 계정별 서버 API로 저장한다. 개발용 관리자 계정은 아래의 별도 오프라인 모드를 사용한다. 백엔드 구현은 수정하지 않았다.

## 서버 없이 관리자 로그인

Android Studio의 기본 Run(Debug)에서 아이디 `admin`, 비밀번호 `admin1234`로 로그인한다. 관리자 로그인을 위한 HTTP 요청은 없으며, 상단에 `관리자 계정`과 `오프라인`을 표시한다. 비밀번호가 틀리면 입장을 거절한다.

신발·러닝 기록은 별도 기기 저장소 `runtrack_admin_records_v1`에 저장되어 화면 회전·로그아웃·앱 재시작 후에도 유지된다. 일반 서버 계정이나 과거 체험용 데이터와 합치거나 서버에 업로드하지 않는다. 앱 삭제·데이터 삭제 시 이 기기의 관리자 기록도 삭제된다.

이 계정은 개발용 Debug 빌드에서만 사용할 수 있고 서버 관리자 권한은 없다. Release 빌드에서는 기존 서버 인증만 사용한다. 날씨는 별도 공개 API이므로 인터넷이 필요하지만 실패해도 관리자 로그인·기록 저장은 가능하다.

## 실행

1. Python 3.11 또는 `uv`가 설치된 PC에서 PowerShell로 다음 파일을 실행한다.

   ```powershell
   & 'C:\2026_2_RunTrack\start-local-api.ps1'
   ```

   필요한 패키지를 처음 한 번 설치하고 별도 `.local-api/runtrack-dev.sqlite3` DB와 개발용 서명 키를 만든다. 기존 백엔드 `.env` 또는 팀의 서버 DB를 변경하지 않는다. 이 폴더는 Git에서 제외되어 있다. 서버를 다시 시작해도 로컬 계정과 기록은 유지된다.

2. PC에서 `http://127.0.0.1:8000/docs` 또는 `/health` 응답을 확인한다.
3. Android Studio에서 `C:\2026_2_RunTrack\android`를 열고 Android Emulator로 Run한다.
4. 일반 계정은 앱에서 이메일을 포함해 회원가입한 뒤 로그인한다. 등록한 서버 계정의 비밀번호를 확인한다.

서버 실행 창을 닫으면 API가 중지된다. 서버가 꺼져 있으면 앱에서 연결 오류가 표시되며, 서버를 다시 실행한 뒤 재시도하면 된다.

## 서버 주소 변경

기본 주소는 에뮬레이터에서 호스트 PC로 접근하는 `http://10.0.2.2:8000/`이다. 별도의 서버는 Gradle 속성 `runtrackApiBaseUrl`로 지정한다.

```powershell
.\gradlew.bat assembleDebug '-PruntrackApiBaseUrl=https://your-server.example/'
```

Android Studio에서 사용할 때는 `android/gradle.properties` 또는 사용자 Gradle 속성에 `runtrackApiBaseUrl=실제서버주소`를 설정하고 Sync 후 다시 실행한다. URL에는 토큰·아이디·비밀번호를 넣지 않는다.

실기기를 USB로 같은 PC에 연결한다면 `adb -s 기기번호 reverse tcp:8000 tcp:8000` 후 앱을 `http://127.0.0.1:8000/` 주소로 빌드할 수 있다. 팀원 PC나 배포 서버에는 담당자가 제공한 접근 가능한 주소가 필요하다.

HTTP 허용은 debug 빌드의 `10.0.2.2`, `127.0.0.1`, `localhost`로 한정했다. 팀 서버·배포 서버는 HTTPS를 사용한다. release 빌드에는 이 debug 네트워크 설정이 포함되지 않는다.

## 현재 연결한 기능

- 회원가입 `POST /api/users/register`, 로그인 `POST /api/users/login`, 내 정보 `GET /api/users/me`.
- 로그인 토큰을 보호된 API에 Bearer 헤더로 전달. 만료 또는 401이면 로그인으로 복귀한다.
- 비밀번호와 토큰은 앱 설정·기록 파일에 저장하지 않는다. 새 앱 프로세스에서는 다시 로그인하고 화면 회전에서는 로그인 상태를 유지한다.
- 신발 목록·등록·편집·삭제 및 서버 누적 거리·횟수 표시.
- 수동 러닝 기록 목록·등록·편집·삭제. 모든 페이지를 조회해 주간 요약·최근 기록을 계산한다.
- 러닝 입력은 기기의 실제 시간대를 붙여 보내고, 서버의 UTC 응답은 기기 시각으로 변환한다.
- 저장 완료 후 서버를 다시 조회한다. 저장 응답 이후 조회만 실패했다면 저장 실패로 안내하거나 같은 POST를 자동 재시도하지 않는다.
- 조회는 끊긴 유휴 연결을 복구할 수 있다. 저장·수정·삭제는 새 연결을 사용하고 자동 재전송하지 않아 중복 생성을 방지한다.
- 로그아웃 시 화면 ViewModel과 계정 데이터를 분리한다. 기기에 남아 있는 과거 체험용 기록은 자동 업로드하지 않는다.

## 백엔드 규격에 따른 화면 조정

| 항목 | 현재 동작 |
|---|---|
| 가입 이름 | 서버가 받지 않아 이메일 입력으로 교체 |
| 아이디 중복 | 요청에 따라 버튼은 ‘중복확인’, 성공 문구는 ‘사용 가능한 아이디입니다’로 표시. 조회 API가 없어 버튼은 입력 형식과 개발용 예약 아이디만 확인하며, 실제 중복은 가입 응답 409로 안내. 백엔드 추가 없음 |
| 러닝 시간 | 1 이상의 정수 분만 입력, 소수 분을 임의로 반올림하지 않음 |
| 페이스·속도 | 거리와 시간으로 서버가 계산 |
| 칼로리 입력 | 서버가 받지 않아 일반 계정에서는 입력을 숨김. 응답에 있는 값은 목록에서 조회 가능. 관리자 모드에서는 기기에 입력·저장 |
| 신발 등록 전 사용량 | 일반 계정에서는 입력을 숨기고 누적값은 서버 응답 사용. 관리자 모드에서는 기기에 입력·저장 |
| 구매 날짜 수정 | 등록 시 입력 가능, 등록 후에는 읽기 전용 |
| 러닝 심박수·기온 수정 | 등록 시 입력 가능, 편집에서는 읽기 전용 |
| 선택값 지우기 | 러닝 신발 연결·메모는 명시적 null로 해제. 신발의 선택 문자열은 빈 문자열로 지움 |
| 신발 삭제 | 러닝 기록은 유지. 과거 신발 이름의 서버 보존 기능은 없어 연결 해제로 안내 |
| AI | 백엔드 실제 구현 전이므로 기존 예시 표시 유지 |
| 날씨 | 백엔드 변경 없이 Open-Meteo 공개 API를 앱에서 직접 호출 |

## 날씨

홈의 주간 요약 아래에서 도시를 선택해 기온·체감온도·습도·풍속·강수량을 확인한다. 기본은 서울이며 선택한 도시는 기기에 기억한다. 실제 기기의 GPS 위치를 조회하거나 전송하지 않는다.

- API: `https://api.open-meteo.com/v1/forecast`, HTTPS.
- 별도의 API 키나 회원가입이 필요 없는 비상업용 무료 API를 사용한다. 이 과제와 같은 교육용 용도에 맞춘 설정이다. 광고·구독·상업 배포 시에는 제공자의 유료 사용 조건을 다시 확인한다.
- 선택 도시의 공개 중심 좌표만 전송한다. RunTrack 로그인 토큰·이메일·기록은 전송하지 않으며 인증 클라이언트와 분리했다.
- 기온 °C, 바람 m/s, 강수 mm를 명시적으로 요청한다. 강수의 집계 시간은 응답 interval에 따라 표시한다.
- 10분 캐시, 같은 도시의 수동 새로고침은 최소 30초 간격. 홈 진입과 앱 복귀 시 필요한 경우 갱신한다.
- 기준 시각은 한국 시간으로 표시한다. 2시간 넘은 자료나 갱신 실패 시 이전 정보임을 표시하고, 누락된 값은 0도로 만들지 않고 `—`로 표시한다.
- 도시 변경 시 이전 도시의 값을 새 도시의 날씨로 표시하지 않는다. 날씨 오류는 로그인·기록 저장에 영향을 주지 않는다.
- 현재 날씨는 관측소 실측이 아니라 예보 모델 기반 정보다. 화면에 Open-Meteo 및 CC BY 4.0 링크를 표시하고 상태명을 한국어로 표기한다.

## 검증 환경

API 단위 테스트는 MockWebServer를 사용하고, 앱 UI 테스트는 로컬 개발 서버에만 테스트 계정을 생성한다. 실제 서버 주소로 UI 테스트를 실행하지 않도록 주소를 검사한다. 팀 서버에 반영하려면 현재 서버의 OpenAPI와 지원 필드를 다시 대조한다.
